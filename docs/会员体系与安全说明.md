## 二、会员与计费规则（默认，可在 config 改）
- `membership.monthly_price_cents = 1000` → 月费 10 元
- `membership.monthly_quota = 1000` → 每月会员赠送 1000 次 AI
- `membership.quota_price_cents = 1000`、`quota_add = 1000` → 10 元购 1000 次

订单类型：`unlock`（解锁报告）/ `subscribe`（会员）/ `quota`（AI 次数充值）；`markPaid` 幂等发货，重复回调不会重复到账。

## 三、安全措施（已实现）
1. **口令**：管理员密码 bcrypt 哈希落库，绝不明文存储；登录接口按 IP 限流（10 次/分）。
2. **会话**：管理后台令牌用 `crypto/rand` 生成，库中只存 SHA-256 哈希，常数时间比对，24 小时过期，懒清理。
3. **SQL 注入**：全部走 GORM 参数化查询；分页参数经 `strconv` 解析后使用。
4. **XSS**：用户内容统一 `sanitizeUserText`（去控制字符+限长），前端一律插值渲染（无 v-html），双重防护。
5. **越权**：`/v1/admin/*` 全部经 `adminAuth` 中间件；社区仅返回 `published` 帖子。
6. **防灌水**：发帖/评论按 IP 限流（10 次/分）；AI 对话限流（30 次/分）+ 会员额度双重控制。
7. **支付安全**：微信回调验签+解密、支付宝回调 RSA2 验签，未验签不发货；`markPaid` 幂等。
8. **异常收敛**：`recoverMiddleware` 兜底 panic，返回通用错误不泄露堆栈；日志只记方法+路径，不含敏感信息。
9. **路径遍历**：静态资源走 `http.FileServer`（内置防目录穿越）；JSON 请求体限制 1MB。

## 四、已知风险与上线前必须处理
1. **轻量身份**：当前用户身份为前端 localStorage 生成的随机 `uid`（`X-User-Id` 头），高熵不可猜测，但**非强认证**。上线接入微信小程序/公众号登录后，应改为 `openid` 绑定并校验签名。
2. **管理员默认密码**：上线前务必更换（见上）；`config.yaml` 含敏感信息，部署后设 `chmod 600`。
3. **AI 密钥**：`ai.api_key` 存于配置，仅后端使用、不返回前端；上线填真实大模型密钥（DeepSeek/通义等 OpenAI 兼容接口）。
4. **CORS**：当前 `Access-Control-Allow-Origin: *`（无 Cookie 依赖、鉴权走请求头，风险可控）；如需更严可收紧为同源。
5. **真实支付**：微信/支付宝需在备案 + HTTPS 就绪后，填入商户号/证书/密钥并将 `payment.provider` 切到 `wechat` 或 `alipay`。
